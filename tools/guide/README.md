# מדריכי הווידאו

הסרטונים ב-`public/guide/` אינם צילומי מסך ידניים: הם **הקלטה של הבנייה
האמיתית** (`dist/`) שרצה בדפדפן ומופעלת בסקריפט, עם שכבת הדרכה מוזרקת מעליה
(כותרת, כיתובית, סמן וטבעת הדגשה). המשמעות: מסך שישתנה בתוכנה ישתנה גם במדריך
בהקלטה הבאה, ואי אפשר שהמדריך יראה משהו שאינו קיים.

## הרצה

```bash
npm run build          # חובה — מקליטים את dist/
node tools/guide/record.mjs        # כל הפרקים
node tools/guide/record.mjs 04     # פרק אחד (לפי חלק מהשם או מה-slug)
```

הפלט: `public/guide/<slug>.webm` + `public/guide/index.json`, שממנו מסך המדריך
בתוכנה בונה את רשימת הפרקים. פרק חדש = קובץ ב-`chapters/` + שורה במערך
`CHAPTERS` שב-`chapters.mjs`; מסך המדריך לא צריך שינוי, וכרטיס הפתיחה
("פרק 3 מתוך 8") נגזר מהמערך.

ריצת בדיקה, בלי לגעת בסרטונים שבריפו:

```bash
GUIDE_OUT=/tmp/rec GUIDE_SHOTS=/tmp/shots GUIDE_NO_COMPRESS=1 node tools/guide/record.mjs 06
```

| משתנה | מה עושה |
|---|---|
| `GUIDE_OUT` | תיקיית הפלט במקום `public/guide/` |
| `GUIDE_DIST` | בנייה אחרת במקום `dist/` |
| `GUIDE_SHOTS` | צילום מסך בכל כיתובית — לבדיקת הזרימה בלי לצפות בסרטון |
| `GUIDE_NO_COMPRESS` | מדלג על הדחיסה (למטה) |

## מבנה

| קובץ | תפקיד |
|---|---|
| `harness.mjs` | שרת ל-dist, דפדפן מוקלט, גשר Electron מדומה, ו-API להנחיה (`say`/`point`/`click`/`card`) |
| `chapters.mjs` | סדר הפרקים |
| `flow.mjs` | מעברים חוזרים בין מסכים (כניסה למשחק במצב שלטים, דיווח ריסיבר) |
| `demoGame.mjs` | משחק הדוגמה — נבנה בקוד כדי שההקלטות יהיו זהות בכל הרצה |
| `sheet.mjs` | קובצי האקסל שבמדריך, דרך **הכותב של התוכנה עצמה** (`src/app/xlsx.ts`) |
| `chapters/*.mjs` | פרק אחד לכל קובץ |

הגשר המדומה מחזיק גם את מה שהתהליך הראשי מחזיק בתוכנה האמיתית, ו-`openGuide`
מקבל אותו כהגדרות: המשחק האחרון (`lastGame` — ZIP, או קוד של משחק מהספרייה),
המשחקים שבמחשב (`library`), משחקים להורדה לפי קוד (`remote`), קוד הגישה
(`gate`), המחשב מול המערכת (`device` — מספר, שם, אישורים ומשחקים שנשלחו) ומצב
העדכון (`update`). באמצע פרק משנים אותם דרך `window.__desk`: `press` (שלט),
`device(patch)` (כאילו הגיע מהמערכת), `update(status)`.

## מגבלות שכדאי להכיר

- **אין קול.** אין מנוע הקראה בסביבה, ולכן ההסבר הוא בכיתוביות. לכן הן גדולות,
  והקצב מותאם לקריאה ולא לדיבור.
- **הקלטה לא נוגעת בשרתים החיים.** כל בקשה החוצה נחסמת, חוץ מ-
  `save-clicker-numbers`, שמקבלת תשובה מדומה שהכול נשמר — כדי שחיווי השמירה
  בפרק השמות ייראה כמו באירוע עם אינטרנט.
- **לחיצה או מקש מבטלים פתיחה אוטומטית.** משחק שנשלח למחשב נפתח לבד רק לפני
  שהמפעיל נגע בתוכנה (`devicePlan.ts`). בפרק 6 הסרטון רק מצביע עד שהמשחק הראשון
  נפתח; `point`/`say` אינם יוצרים אירועי עכבר.
- **שמות קבצים ל-`setInputFiles` חייבים להיות ASCII.** Playwright מצרף קובץ בשם
  עברי בשקט — בלי שגיאה ובלי קובץ. הקבצים נכתבים בשמות אנגליים; השם אינו נראה
  בסרטון ממילא.
- **דחיסה.** Playwright מקליט VP8 בקצב קבוע; אחרי כל ההקלטות `record.mjs` מקודד
  כל סרטון מחדש ל-VP9 (CRF 36) עם ffmpeg — בערך פי 3 קטן יותר, בלי הבדל נראה
  בטקסט. הדחיסה רצה בסוף ולא בין פרקים, כי ffmpeg על כל המעבדים בזמן הקלטה גורם
  לדפדפן להפיל פריימים. בלי ffmpeg נשארים הקבצים המקוריים. כל פרק הוא הקלטה
  רציפה אחת, בלי חיתוך וחיבור.
- **הקלטה חוזרת מחליפה את כל הבייטים** של כל סרטון: הסרטונים ארוזים בתוכנה,
  וסרטון שהוקלט מחדש יורד במלואו בעדכון הבא של כל מחשב (העדכון ההפרשי לא עוזר
  כאן). שווה לזכור לפני שמקליטים מחדש בלי צורך — כל הקלטה גם מוסיפה את מלוא
  הנפח להיסטוריית ה-git.
